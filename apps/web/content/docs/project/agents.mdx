title: Agents
description: Logical agents select immutable OpenCode, Claude Code, Codex, or Pi runtime profiles.

An agent is the logical name a project uses to start a [session](/docs/work/sessions). The agent selects one immutable runtime profile. The profile selects OpenCode, Claude Code, Codex, or Pi.

## Runtime modes

- Version 2 runs OpenCode.
- Version 3 runs the harness selected by `agents.<name>.runtime`.

Version 3 requires the project experiment named **ACP & Multi-Harness**. The default remains OpenCode over REST.

## Version 3 logical agents

Version 3 separates three identifiers.

| Identifier | Purpose |
|---|---|
| Logical agent | Project-facing name passed as `agent_name`. |
| Runtime profile | Immutable manifest profile selected by the logical agent. |
| Native agent | Optional harness-native agent or mode in `agents.<name>.agent`. |

```yaml
kortix_version: 3
default_agent: reviewer

runtimes:
  codex:
    harness: codex
    config_dir: .codex

agents:
  reviewer:
    runtime: codex
    agent: reviewer
    connectors: [github]
    skills: [code-review]
```

Kortix compiles this mapping when it creates the session. The session stores `runtime_name`, `runtime_harness`, and `native_agent`. A later UI agent selection cannot change these values.

## Version 2 OpenCode agents

Each v2 agent has two parts.

- **Behavior** — `.kortix/opencode/agents/<name>.md`.
- **Governance** — the matching `agents.<name>` block in `kortix.yaml`.

The Markdown frontmatter sets OpenCode behavior. The manifest sets connectors, secrets, skills, and CLI grants.

## Governance is deny-by-default

An agent with no `connectors`, `secrets`, `skills`, or `kortix_cli` key gets
none of that access. Set a field to `all` to grant full access, or list
specific names. `default_agent` in `kortix.yaml` names the agent a session
starts when you request no agent.

Legacy `kortix.toml` (v1) projects list agents in an array, not a map, and
grant full access by default. Set specific grants to restrict access. See
[the manifest reference](/docs/project/manifest).

## Skills give an agent know-how

A v2 OpenCode skill is a Markdown file at `.kortix/opencode/skills/<name>/SKILL.md`. The `skills` grant controls which skills the agent may load. Version 3 applies the same grant boundary to the selected harness.

## How a session picks its agent

Creating a session accepts `agent_name`. Kortix uses `default_agent` when the field is absent. The selected agent remains fixed for the session.

An agent never exceeds the access of the person or token that started the
session.

New or changed agents and skills reach future sessions only after a
[change request](/docs/work/change-requests) merges them into the default
branch. Connect external tools before an agent can use them; see
[Connectors](/docs/connect/connectors).
